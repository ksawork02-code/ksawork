# 산업일자리전환 컨설팅 관리 앱 — 설치 가이드

구글 시트(DB) + 구글 드라이브(파일) + 앱스크립트 웹앱으로 Lark Base를 대체합니다.

## 파일 구성

| 파일 | 앱스크립트에서 만들 이름 | 역할 |
|---|---|---|
| appsscript.json | (프로젝트 설정에서 표시 후 덮어쓰기) | 시간대·웹앱 설정 |
| Code.gs | `Code` (스크립트) | 서버: DB, 로그인, 업무 기능, 메일, 매일 점검 |
| Migrate.gs | `Migrate` (스크립트) | Lark → 구글 이관 (첨부파일 다운로드) |
| Sync.gs | `Sync` (스크립트) | Lark → 앱 동기화 엔진 (최초 이관 + 전환 기간 자동 동기화) |
| Features.gs | `Features` (스크립트) | 세부 기능: 일정·서류·체크리스트·만족도·교육·정산·추천·실적·공지·문의·진행조회·문자 |
| Index.html | `Index` (HTML) | 관리자·컨설턴트 화면 틀 |
| App.html | `App` (HTML) | 관리자·컨설턴트 화면 기능 |
| App2.html | `App2` (HTML) | 세부 기능 화면 |
| Form.html | `Form` (HTML) | 외부 신청폼 3종 |
| Common.html | `Common` (HTML) | 공통 기능 |
| Styles.html | `Styles` (HTML) | 디자인 |

## 설치 순서 (약 20분)

1. **구글 시트 만들기**: 앱을 운영할 구글 계정으로 드라이브에서 새 스프레드시트를 만듭니다(예: `산업일자리전환 컨설팅 DB`).
2. **앱스크립트 열기**: 시트 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. **매니페스트**: 왼쪽 ⚙️ **프로젝트 설정 → "appsscript.json 매니페스트 파일 표시"**를 체크합니다. 편집기에 생긴 `appsscript.json` 내용을 이 패키지의 `appsscript.json`으로 바꿉니다.
4. **코드 붙여넣기**
   - 기본 `Code.gs` 내용을 지우고 `Code.gs` 내용을 붙여넣습니다.
   - **＋ → 스크립트**로 `Migrate`, `Sync`, `Features`를 만들어 같은 이름의 .gs 내용을 붙여넣습니다.
   - **＋ → HTML**로 `Index`, `App`, `App2`, `Form`, `Common`, `Styles` 6개를 만들어 각각 붙여넣습니다. 이름에 `.html`은 붙이지 않습니다.
   - 💾 저장합니다.
5. **초기 설정**: 위쪽 함수 선택에서 `setup`을 고르고 ▶ 실행합니다.
   - 권한 요청이 뜨면 계정을 선택합니다. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다. 내가 만든 스크립트라 정상입니다.
   - 시트 11개와 드라이브 폴더 `산업일자리전환 컨설팅 앱 파일`이 생기고, 매일 오전 8시 점검 트리거가 등록됩니다.
6. **Lark 데이터 이관**: 시트를 새로고침하면 메뉴 **컨설팅 관리**가 생깁니다. **Lark 데이터 이관**을 누르고 Lark App Secret을 입력합니다.
   - 데이터(신청 225, 사업장 215, 컨설턴트 약 100명, 교육이수)는 1분 안에 옮겨집니다.
   - 첨부파일(약 770개, 575MB)은 5분 단위로 **자동으로 이어서** 진행됩니다. 브라우저를 닫아도 됩니다.
   - **컨설팅 관리 → 이관 진행상황 보기**로 남은 파일 수를 확인합니다. 완료되면 관리자 메일로 알려 주고, 저장했던 App Secret은 자동으로 지웁니다. Lark 콘솔에서 Secret을 재발급하는 것을 권장합니다.
   - **전환 기간에 Lark도 계속 쓴다면**: 이관 전에 시트 메뉴 **컨설팅 관리 → Lark 자동 동기화 켜기**를 누르세요(간격 5·10·15·30분). App Secret이 유지되고, Lark에서 새로 들어오거나 바뀐 내용이 자동으로 앱에 반영됩니다. 전환이 끝나면 앱의 설정 탭에서 **동기화 끄기**를 누르면 Secret이 삭제됩니다.
7. **웹앱 배포**: 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**을 고릅니다.
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
   - 배포한 뒤 나오는 **웹 앱 URL**을 복사합니다. 이 주소를 한 번 열면 설정에 자동으로 기록되어 메일 링크에 쓰입니다.
8. **관리자 로그인**: 웹앱 URL을 열고 `ksawork02@gmail.com`으로 인증코드를 받아 로그인합니다. **설정** 탭에서 아래를 확인합니다.
   - `ADMIN_EMAILS`: 관리자 이메일(쉼표로 구분)
   - `RESUME_TEMPLATE_URL`, `APPLY_TEMPLATE_URL`: 이력서·신청서 양식 다운로드 링크
   - `FILE_EXT_신청서`, `FILE_EXT_보고서`, `FILE_BLOCK_EXT`: 업로드 허용·차단 확장자(기본 hwpx만 허용, hwp 차단)
9. **링크 배포**: **설정** 탭 위쪽 "배포 링크"를 공유합니다.
   - 기업 신청폼 `…/exec?page=apply`
   - 차년도 사전접수 `…/exec?page=pre`
   - 컨설턴트 신청폼 `…/exec?page=consultant`
   - 로그인(관리자·컨설턴트) `…/exec`
10. **컨설턴트 안내**: **메일** 탭 → "활동 중인 외부 컨설턴트 전체"를 고르고 `{{앱URL}}`을 넣어 접속 안내를 보냅니다.

## 세부 기능 설정 (설정 탭)

| 기능 | 설정할 것 |
|---|---|
| 협약·착수 서류 | `DOC_TYPES` — 필수 서류 종류(쉼표 구분) |
| 검수 체크리스트 | `CHECKLIST_중간` / `_최종` / `_사후` — 한 줄에 한 항목 |
| 만족도 설문 | `SURVEY_QUESTIONS`(한 줄에 한 문항, 5점 척도), `SURVEY_SUBJECT`/`SURVEY_BODY` |
| 방문 일정 | `CALENDAR_SYNC`(Y/N), `CALENDAR_ID`(비우면 운영 계정 기본 캘린더) |
| 수당 정산 | [정산] 탭의 **수당 기준** 표에 항목·보고서·금액·분배를 입력 (금액이 있어야 정산 내역이 생김) |
| 기업 진행조회 | `STATUS_LOOKUP_OPEN`(Y/N). 주소: `…/exec?page=status` (넷리파이 `/status`) |
| 월간 실적 메일 | `MONTHLY_REPORT_MAIL`(Y/N) — 매월 1일 아침 전월 요약 |
| 문자(솔라피) | 솔라피 가입 → API Key 발급 → 발신번호 등록 → 설정 탭 [문자 설정]에 키 저장, `SMS_ENABLED=Y`, `SMS_SENDER`=발신번호. `SMS_ON_REMIND`/`SMS_ON_SUPPLEMENT`/`SMS_ON_VISIT`로 자동 문자 선택 |

처음 붙여넣을 때 `setup`을 한 번 더 실행하면 새 시트(일정·서류·만족도·교육신청·수당기준·정산·공지·공지읽음·문의)와 설정 항목이 추가됩니다. 기존 데이터는 그대로 둡니다. 구글 캘린더 권한 요청이 새로 뜨면 허용합니다.

## Lark 동기화 규칙 (전환 기간)

- 방향: **Lark → 앱 한쪽**입니다. 앱에서 입력한 내용은 Lark로 가지 않습니다.
- 새 레코드는 추가하고, 지난 동기화 이후 **Lark에서 바뀐 칸만** 앱에 반영합니다. 앱에서만 고친 값은 유지됩니다.
- 같은 칸을 양쪽에서 고쳤다면 Lark 값이 우선합니다. 덮어쓴 이전 값은 변경이력에 `Lark동기화`로 남습니다.
- Lark 신청이 앱 신청과 사업자번호가 겹치면 비고에 `[동기화 중복의심]`을 표시합니다.
- 비교 기준값은 숨김 시트 `_Lark동기화`에 저장됩니다. 지우지 마세요.
- 무료 gmail 계정은 트리거 실행 시간이 하루 90분으로 제한되므로 간격은 30분을 권장합니다(1회 약 20~40초).

## 코드를 고친 뒤에는

**배포 → 배포 관리 → ✏️ 수정 → 버전: 새 버전 → 배포**를 해야 웹앱에 반영됩니다. URL은 바뀌지 않습니다.

## 운영 메모

- **로그인**: 이메일 인증코드(6자리) 방식입니다. 관리자는 `ADMIN_EMAILS`, 컨설턴트는 컨설턴트 시트의 이메일로 로그인합니다. 한 번 로그인하면 그 기기에서 30일간 유지됩니다. 상태를 `제외`로 바꾸면 최대 10분 안에 접속이 차단됩니다.
- **메일 한도**: gmail.com 계정은 하루 약 100명에게 보낼 수 있습니다. 남은 한도가 15건 이하가 되면 로그인 코드만 보내고 다른 알림은 보류합니다(메일 탭의 발송 이력에서 확인). Google Workspace 계정으로 운영하면 하루 1,500명까지 보낼 수 있습니다.
- **동시 사용**: 80명 이상이 접속해도 무리 없습니다(동시 처리 한도 30건, 요청 1건에 1~2초).
- **이메일이 없는 컨설턴트 5명**(손정란(S), 김일터, 손정란, 김표준, 표일터)은 로그인할 수 없습니다. 실제 인원이면 컨설턴트 탭에서 이메일을 입력해 주세요.
- **Lark에서 바뀐 점**
  - 사업장 관리의 각 날짜(착수·종료·보고서 기한)를 **차수일정** 시트로 묶었습니다. 사업장을 만들 때 차수 일정이 자동으로 들어가고, 일괄 적용도 할 수 있습니다.
  - '사업장관리추가' 버튼은 신청 상세의 **사업장 생성**으로, '수행일지 바로가기' 버튼은 앱의 **수행일지** 기능으로 바꿨습니다. 기존 작성회차는 `수행일지_이관` 열에 보존했습니다.
  - Lark 수식(사업장 지역, 수행건수, 정책연계 건수, 총 교육시간)은 앱이 자동으로 계산합니다.
  - Lark 사용자 필드(인원, 컨설턴트계정)는 이름이 익명으로 내려와서 옮기지 않았습니다. 컨설턴트는 명단의 연결로 대응했습니다.
  - 완료된 '비대면 설명회 설문'은 `보관_설명회설문` 시트에 보관했습니다.
- **시트 직접 수정**: 가능합니다. 다만 1행 헤더와 `ID` 열은 바꾸지 마세요. 파일 열(신청서 등)은 JSON 형식이므로 앱에서만 수정하는 것이 안전합니다.

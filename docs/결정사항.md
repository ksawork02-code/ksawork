# 설계 결정 기록 (2026-11-07 ~ 11-08 Cowork 세션)

| 주제 | 결정 | 이유 |
|---|---|---|
| 플랫폼 | Google Apps Script 웹앱 + 구글 시트(DB) + 드라이브(파일) | 비용 0, 기관 구글 계정으로 운영, 별도 서버 불필요 |
| Lark 대체 방식 | 완전 이전 + 전환 기간 **Lark → 앱 단방향** 자동 동기화 | 양방향은 충돌 위험 큼. 필드 단위 병합: Lark에서 바뀐 칸만 반영, 같은 칸 충돌 시 Lark 우선(변경이력에 이전 값) |
| 로그인 | 이메일 6자리 OTP, 비밀번호 없음, 기기별 30일 토큰(스크립트 속성), 권한은 매 요청 시 시트 기준 재판정(10분 캐시) | gmail 계정은 웹앱에서 사용자 이메일을 알 수 없음. 컨설턴트 계정 = Lark 명단 이메일 |
| 웹앱 배포 | 실행: 나(USER_DEPLOYING), 액세스: 모든 사용자(익명) | 외부 기업 신청폼 + 컨설턴트가 시트 권한 없이 사용 |
| 메일 한도 | gmail 100명/일 → 마지막 15건은 로그인 코드용 예약(`MAIL_RESERVE`), 기한 알림은 컨설턴트별 1통으로 묶음 | Workspace 계정이면 1,500명/일 (권장) |
| 업로드 | 신청서·보고서는 `.hwpx`만, 전체 `.hwp` 차단, HWPX는 ZIP 매직바이트(PK) 검사 | 검수 자동화 스킬이 HWPX만 처리 |
| 파일 접근 | 드라이브 파일은 공유하지 않고 `downloadFile`이 권한 확인 후 base64 전달 | 사업자등록증 등 개인정보 보호 |
| 주소 | 넷리파이 정적 페이지가 웹앱을 iframe으로 감쌈(`/apply` `/pre` `/consultant` `/status` `/survey`), `PUBLIC_URL` 설정 시 메일 링크도 넷리파이 주소 | 앱스크립트 URL에 커스텀 도메인 불가 |
| 차수 일정 | 사업장별 날짜를 `차수일정` 시트로 분리, 생성 시 자동 입력, 일괄 적용 버튼 | Lark에서 같은 날짜를 사업장마다 반복 입력하던 문제 |
| 정산 | `수당기준` 표(항목·보고서·금액·분배) 금액이 있을 때만, 보고서 검수완료 시 정산 행 자동 생성(중복 방지) | 금액 규칙 미정 → 운영자가 입력 |
| 문자 | 솔라피 v4 API(HMAC-SHA256), 키는 스크립트 속성 | 알리고는 발송 IP 등록 필요(앱스크립트 IP 가변) |
| 테스트 | Node 모의 Apps Script(`test/gas-mock.js`) + 실제 Lark 데이터 + Playwright UI | 앱스크립트 실환경 없이 로직·화면 검증 |

## 아직 실환경에서 검증하지 못한 것
- 실제 Apps Script 실행(권한 승인, 6분 제한, 트리거, LockService, CacheService 동작)
- 드라이브 실제 업로드/다운로드, 엑셀 내보내기(export URL + OAuth 토큰)
- 구글 캘린더 이벤트 생성, 솔라피 실제 발송
- 넷리파이 iframe 안에서의 localStorage(사파리 ITP), 회사 보안 프로그램 차단 여부
- 메일 실제 도달(스팸함)
